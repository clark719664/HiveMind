# HiveMind Swarm Lab: static site and game

A single-page static site (`index.html`) and a small game (`game.html`, "Quorum Quest") built on a JavaScript port of the Python Swarm Lab toy
(`src/hivemind/lab/swarm_lab.py`, guide in `docs/community/SWARM_LAB.md`).

**What it is, and what it is not.** It is an educational, qualitative analogy of the effect measured in the real E13/E14 swarm experiments. It is
not a reproduction of them: the toy's defaults were chosen to make the effect visible and its numbers must never be quoted as results about real
LLM training. The "What the real experiments measured" panel shows the real numbers, each tagged with its source file and receipt hash prefix. No
peer review of record exists for the project. All references to `$HIVE` and "Points" (PTS) refer exclusively to internal, non-monetary,
non-transferable accounting units measuring contributed and reciprocal computing power, and NO MONEY, FIAT CURRENCY, CRYPTOCURRENCY, FINANCIAL
INSTRUMENT, SECURITY, WAGE, OR MONETARY PAYMENT OF ANY KIND IS OR WILL EVER BE INVOLVED, PROMISED, OWED, OR PAID (see
`LEGAL_DISCLAIMER_AND_COMPUTE_RECIPROCITY.md`); the game score is a "learning score", not PTS or `$HIVE`.

## Open it locally

No build step, no dependency, no network. Either open `docs/site/index.html` directly (it works from `file://`) or serve the folder:

```bash
python3 -m http.server -d docs/site 8000     # then browse to http://localhost:8000
```

Requests made by the pages: none. There are no CDN scripts, fonts, analytics or remote images; charts are inline SVG. No cookies; `localStorage` is
used (inside try/catch) only for the theme, the last Swarm Lab scenario and the game's best scores.

## Files

| File | Role |
| :-- | :-- |
| `index.html`, `style.css`, `app.js` | the page, its styles (light/dark, responsive from 360 px) and the UI glue + shared SVG/table renderers (`SwarmSite`) |
| `swarm_lab.js` | the engine: UMD classic script, global `SwarmLab`, also `require("./swarm_lab.js")` under node. No dependency, no DOM |
| `game.html`, `game.js` | Quorum Quest; `game.js` exposes the DOM-free levels, scoring and debrief as `GameLogic` |
| `data.js` | `window.HM_DATA = {...}` with the measured results, generated by `scripts/build_site_data.py`; do not edit by hand |
| `parity_driver.js` | node driver used only by `tests/test_swarm_lab_js_parity.py` |

## Keeping the JavaScript engine identical to Python

`swarm_lab.js` follows the contract in the docstring of `swarm_lab.py` (PRNG, operation order, outer step, retention). The scenario fields keep their
Python names (`straggle_every`, `churn_start`, ...), so JSON scenarios are interchangeable. Check it with:

```bash
python3 -m pytest tests/test_swarm_lab.py tests/test_swarm_lab_js_parity.py tests/test_site_static.py tests/test_build_site_data.py
```

The parity test runs about 550 scenarios (presets x seeds 1-5 x policies x straggle modes x K, plus edge cases) through node and compares loss
curves, admitted/late/required/carried lists, round times and totals with Python to 1e-9 (it needs `node` on `PATH` and skips with a message otherwise).

## Regenerate `data.js`

```bash
python3 scripts/build_site_data.py          # reads artifacts/experiments/*.json, writes docs/site/data.js
```

The builder copies values and status strings verbatim and never invents a number; a missing source file gives `{"available": false}` for its block and
the page says so. Run it again when a report appears (for example `E14_report_<model>.json` or `E15_gwaya_rft_report.json`) and commit the new `data.js`.
Its only computed value, the rotating-straggler retention, is flagged `derived`.

## Add a policy or a level (contribution guide)

1. **Policy.** Add it to `POLICIES` and to the round loop in `src/hivemind/lab/swarm_lab.py`, with tests in `tests/test_swarm_lab.py`; then make the same
   change in `swarm_lab.js` (the operation order must stay identical) and add the policy to the `<select id="lab-policy">` in `index.html` and to
   `POLICY_CARDS` in `game.js`. Extend the grid in `tests/test_swarm_lab_js_parity.py` if needed; it must stay under 60 s.
2. **Straggle pattern or churn.** Same two engines (`_penalised` / `penalised`), plus the `<select id="lab-straggle">` options.
3. **Game level.** Append an object to `LEVELS` in `game.js` (id, title, seed, rounds, `scenario`, optional `maxK` and `budgetPerRound`, story, goal, lesson
   and a link to the matching real experiment). Stars need no hand tuning: they are computed from the engine by trying every strategy the cards allow.
   Scoring rule: learning score = 100 x retention (capped at 1) minus 5 points per simulated time unit above the budget (budget levels only), never below
   0. Stars: 3 at >= 95 %, 2 at >= 80 %, 1 at >= 50 % of the best mean score over three consecutive seeds.
4. **A new measured block.** Add a reader in `scripts/build_site_data.py` (with a synthetic-artifact test in `tests/test_build_site_data.py`) and a renderer in
   `app.js`; every block needs a source file, a receipt prefix, its status string verbatim and a "what this does not show" line.

Keep each JavaScript file readable (no minification) and dependency-free, and do not tune the toy to chase the real experiments' numbers.

## Accessibility notes

- Keyboard: every control is a native form element or button; a skip link, visible focus rings (`:focus-visible`) and a logical tab order are provided.
  Game strategy cards are radio buttons, so arrow keys and space work.
- Charts are inline SVG with `role="img"`, a `<title>` and a `<desc>` stating the key numbers; shapes and dash patterns (not colour alone) distinguish the series,
  and every chart has a table equivalent (per-round table, policy comparison table, status letters A/L/R in the strip).
- Results and run summaries are announced through `aria-live` regions. The theme toggle is a button with `aria-pressed`; light/dark follows
  `prefers-color-scheme` until the visitor chooses.
- `prefers-reduced-motion`: the game skips its round-by-round animation and CSS animations/transitions are disabled.
- Layout is fluid down to 360 px; tables scroll horizontally inside their own container. These points are checked structurally by
  `tests/test_site_static.py`, not by rendering in a browser.
