## 2. Definition of Done for any task (all items, no exceptions)

1. **Tests**: new behaviour has tests with at least two real assertions each; pure functions get
   Hypothesis properties; no test may be a tautology; mocks only for external I/O.
2. **No stubs, no fake data**: no `pass` / `...` / `NotImplementedError` bodies, no `mock_` or
   `dummy_` data outside `tests/`; a stage that cannot run reports `BLOCKED`, it does not simulate.
3. **Controls**: an experiment task ships its positive control, its negative control and, for a
   policy, the matched-random control, in the same script. A control that cannot fail is a bug.
4. **Artifacts, not prose**: results land in `artifacts/experiments/E<n>_report.json` with
   `receipt_sha256`, generated by a committed script; figures are regenerated from the JSON.
5. **No scripted verdicts**: no script may write a score, grade, "ACCEPT" or a model name into a
   report unless that model was actually called through `anse.core.api_extractor.APIExtractor`
   with the transcript committed. `paper/autoevolve_peer_review_pipeline.py` is the only
   permitted static audit and it says `is_peer_review: false`.
6. **Citations**: every new arXiv identifier is opened (alphaXiv or arXiv) before it is written
   anywhere; title and author list are copied from the paper, not from memory. The three citation
   files (`docs/ACKNOWLEDGMENTS_AND_CITATIONS.md`, `wiki/…`, `CITATION.cff`) are regenerated
   from one list, never hand-edited.
7. **Verification commands pass** before a PR is opened:

   ```bash
   PYTHONPATH=src python -m pytest tests/ -q -p no:cacheprovider
   cd lean4 && lake build && cd ..
   PYTHONPATH=src python scripts/verify_decoupled_diloco_quorum.py
   PYTHONPATH=src python paper/autoevolve_peer_review_pipeline.py   # scripted audit, 30/30 PROV
   PYTHONPATH=src python scripts/run_experiment_E5_het.py            # ~20 min on 8 CPUs; controls must pass
   PYTHONPATH=src python scripts/update_predictions_ledger.py        # statuses copied from artifacts, never typed
   PYTHONPATH=src python scripts/run_experiment_E10_lattice.py       # ~1 min; E8/Z8/sign codecs, controls must pass
   python -m anse.formal.lean_runner lean4/HiveMindSpec.lean          # from the AutoevolveAI root: independent Lean gate, 120/120
   ```

   Two pre-existing failures are known and environmental (UDP hole-punch tests fail with
   `PermissionError` on `sendto` in sandboxes without raw socket permission):
   `tests/test_cov_core_and_swarm.py::test_async_quic_geo_ring_transport_methods`,
   `tests/test_cov_game_and_client.py::test_rtx_steam_tool_deployer_fast`, and
   `tests/test_rtx_gpu_intense_stress.py::test_season3_rtx_fused_moe_fp8_nat_hole_punch_and_21_lean4_theorems`.
   Do not mark them skipped to make CI green; fix the socket permission or run them on a host that has it.
8. **Paper numbers**: you never edit a number in `paper/hivemind_foundation_article.tex`. You add
   the artifact and a `PROV-*` check; the scientific lead pastes the number.

## 3. Branch, PR and orchestrator protocol

- Branch names as in `ROADMAP.md` (`feat/s9-…`, `formal/s9-…`, `governance/s9-…`); one task per PR.
- PR description must name the RQ/experiment it serves and list the artifact(s) it produces.
- `community_orchestrator.py` (hourly) may claim branches, run the PR security scanner and post
  status; it must not merge a PR whose Definition of Done checklist is incomplete, and it must not
  write to `paper/` or to the citation files.
- Merged-PR counts in `ROADMAP.md` §1 are copied from `gh pr list --state merged`, never typed.

## 4. Reporting back to the scientific lead

After each task: a memo of at most one page in the PR description (not a separate document) with
(a) what was run, (b) deviations from the pre-registered spec, (c) the artifact path and receipt,
(d) raw numbers with seeds and CIs, (e) open problems. No interpretation of whether a prediction
held; that is decided by the scientific lead and recorded in `artifacts/predictions_ledger.json`.

## 5. Things the coordinator decides alone

Tooling, CI configuration, branch strategy, task splitting, assignment of community
contributors, release tagging, orchestrator cadence, performance engineering that does not change
a metric's definition. If a change would alter *what* is measured (metric, cells, seeds, controls,
acceptance rule), it is a `spec-change` and goes to the scientific lead before the run.
